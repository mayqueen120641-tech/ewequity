# EweQuity — 배포 & 연동 가이드

전달드린 파일 3개는 이렇게 쓰시면 됩니다.

```
API_발급_가이드.md   ← 5개 API 키 발급 방법 (먼저 진행)
Code.gs              ← Google Apps Script 백엔드 (API 프록시)
index.html           ← 대시보드 화면 (지금 바로 열어봐도 목업 데이터로 확인 가능)
```

지금 바로 `index.html`을 더블클릭해서 브라우저로 열면, 아직 API 키가 없어도 **목업(가짜) 데이터**로 화면 레이아웃을 확인할 수 있어요. (상단에 노란 배너로 "목업 데이터 표시 중"이라고 안내됩니다.)

---

## 1단계 — Google Apps Script 프로젝트 만들기

1. https://script.google.com 접속 → "새 프로젝트"
2. 기본 생성된 `Code.gs` 내용을 전부 지우고, 전달드린 `Code.gs` 내용을 붙여넣기
3. 좌측 톱니바퀴 아이콘(프로젝트 설정) 클릭 → 맨 아래 "스크립트 속성" 섹션에서 "스크립트 속성 추가" 클릭 후 아래 5개를 등록

   | 속성 | 값 |
   |---|---|
   | `ECOS_API_KEY` | 한국은행에서 발급받은 인증키 |
   | `FRED_API_KEY` | FRED에서 발급받은 키 |
   | `FINNHUB_API_KEY` | Finnhub에서 발급받은 키 |
   | `NAVER_CLIENT_ID` | 네이버 개발자센터 Client ID |
   | `NAVER_CLIENT_SECRET` | 네이버 개발자센터 Client Secret |

4. 저장

## 2단계 — 웹 앱으로 배포

1. 우측 상단 "배포" → "새 배포"
2. 유형 선택(톱니바퀴)에서 "웹 앱" 선택
3. 설정:
   - 실행할 사용자: **나(본인 계정)**
   - 액세스 권한: **모든 사용자** (프론트엔드에서 로그인 없이 호출해야 하므로)
4. "배포" 클릭 → 처음엔 권한 승인 화면이 뜨는데, 본인 계정으로 승인
5. 배포 완료 후 나오는 **웹 앱 URL**을 복사 (`https://script.google.com/macros/s/여기.../exec` 형태)

> 💡 코드를 수정할 때마다 "배포 관리 → 수정 → 새 버전"으로 다시 배포해야 변경사항이 반영돼요. URL은 그대로 유지됩니다.

## 3단계 — 프론트엔드에 연결

`index.html` 파일을 열어서 상단부의 이 줄을 찾으세요.

```js
const GAS_URL = "PASTE_YOUR_GAS_WEB_APP_URL_HERE";
```

`PASTE_YOUR_GAS_WEB_APP_URL_HERE` 부분을 2단계에서 복사한 웹 앱 URL로 바꿔주세요. 저장 후 다시 브라우저에서 열면 노란 배너가 사라지고 **실제 API 데이터**가 표시됩니다.

## 4단계 — 동작 확인 체크리스트

- [ ] 5개 지표 카드에 실제 값이 뜨는지 (에러 문구 없이)
- [ ] 히스토리 차트에서 1M/3M/1Y 버튼을 눌러보고 그래프가 바뀌는지
- [ ] 경제 캘린더에 항목이 표시되는지 (Finnhub 무료플랜은 미국 상장사 위주라 삼성전자 등 국내 종목은 안 뜰 수 있어요 — 이 경우 캘린더 항목을 직접 수기로 관리하는 방식으로 바꾸는 것도 방법)
- [ ] 뉴스 피드 카테고리 버튼을 눌러 필터링이 잘 되는지

콘솔(F12 → Console 탭)에 에러가 뜨면, 어떤 지표(rates/history/calendar/news)에서 나는 에러인지 저에게 알려주시면 바로 봐드릴게요.

## 5단계 — 어디서든 접속하게 하려면 (선택)

지금은 `index.html`을 내 컴퓨터에서 여는 방식이라 본인만 볼 수 있어요. "웹사이트처럼" 다른 기기에서도 보고 싶다면:

- **GitHub Pages**: 무료, `index.html`만 올리면 바로 URL 생성됨
- **Netlify / Vercel**: 무료, 드래그 앤 드롭으로 배포 가능

둘 다 정적 파일 호스팅이라 `index.html` 하나만 올리면 끝이에요. GAS_URL은 백엔드이므로 그대로 두면 됩니다.

## 참고 — 알아두면 좋은 것들

- **캐싱**: Code.gs는 지표는 15분, 히스토리는 1시간, 캘린더는 6시간, 뉴스는 30분 동안 캐시해서 같은 데이터를 반복 요청하지 않도록 했어요. API 호출 한도(특히 네이버 뉴스, Finnhub 무료플랜)를 아끼기 위함입니다.
- **에러 처리**: 5개 지표 중 하나라도 실패해도 나머지는 정상 표시되도록 각 지표를 개별적으로 try/catch 했어요 (`safe_` 함수).
- **AI 한 줄 요약(3주차 예정 기능)**: Code.gs 맨 아래 `getAIBriefing()` 함수를 만들어뒀어요. 나중에 Claude API 키를 스크립트 속성에 `ANTHROPIC_API_KEY`로 추가하고, `doGet`의 switch문에 `case 'briefing': result = getAIBriefing(); break;`을 추가하면 바로 쓸 수 있습니다.
- **보안**: API 키는 전부 스크립트 속성(서버 측)에만 있고 index.html(클라이언트)에는 절대 노출되지 않아요. 기획서의 보안 원칙 그대로예요.
